Hydrozoa compiles your Java to WebAssembly and runs it on the brain in an interpreter. This page covers getting it there, seeing what it prints, and fixing what goes wrong.

Uploading

./gradlew hydrozoaUpload                     # a project from the VS Code extension
./gradlew :template:hydrozoaUpload           # in the library's repository (slot 1)
./gradlew :examples:clawbot:hydrozoaUpload   # slot 2

Each robot's build.gradle.kts sets the program's name, slot (1–8) and icon in its hydrozoa { } block. hydrozoa.bin is the Hydrozoa runtime, uploaded with your program (from vexide/Hydrozoa-Java, MIT license). Upload over USB to the brain, or to a controller tethered or radio-linked to it.

Reading output

System.out.println and Telemetry go to the brain's USB serial port. Watch them on the dashboard (Chrome or Edge), or with any serial terminal. An uncaught exception prints over serial and shows on the brain's screen.

Messages you might see

MessageMeaning and fix
[HAL] motor on port N: …The motor isn't plugged in, or something else is on that port. Printed once; commands to it are skipped. Check the cable and Constants.java.
[HAL] no Inertial Sensor found on port NWrong port or loose cable. Heading reads 0 until it's found.
[HAL] Inertial Sensor … reports an error / never started calibrating / calibration timed outRe-seat the cable; make sure the robot is still at startup. A sensor that keeps failing may be damaged.
[HAL] no Rotation Sensor / Distance Sensor / Optical Sensor / GPS Sensor found on port NSame: port or cable. Reads return a safe value (0, NaN or the last reading).
Port N has already been usedTwo devices are set to the same smart port. Thrown at startup so it can't go unnoticed.
3-wire port X has already been usedSame for 3-wire ports. Note that an AdiEncoder uses two ports.
[VexMotor] port N: current limit … outside 0-2.5 AThe config asked for more than a V5 motor allows; 2.5 A was used.
[NamedCommands] no command registered as '…'An auto used a name you didn't register (or registered after building the auto). That step does nothing.
HAL.set(...) must be called before creating the robotSomething created hardware before Main or SimMain set up the hardware layer; e.g. a static field holding a motor. Make it an instance field.
Uploading: hydrozoa: command not foundInstall the Hydrozoa CLI (cargo install --git https://github.com/vexide/hydrozoa-cli.git) and make sure ~/.cargo/bin is on your PATH. The VS Code extension finds it there automatically.
Build: Could not resolve io.github.kedrickjohnson:vexlibGradle can't reach the library's site and has no offline copy. Open the project once in VS Code with the extension installed (it installs the offline copy), or connect to the internet.

The robot does something odd

SymptomLikely cause
Drives in circles when going straightOne side's motors are reversed wrong, or a follower's direction is wrong. Prop the robot up and check each wheel.
Turns stop a few degrees shortkS is too low: run tuning test A.
Turns oscillatekTurnP too high or kTurnD too low: run tuning test B.
Odometry distance is off by a constant factorWrong wheel diameter, gear ratio or cartridge. Run tuning test X.
Odometry position drifts while turning in placeTrack width (drive odometry) or tracking-wheel offsets are off. See Odometry.
Heading drifts all matchThe robot moved during IMU calibration. Keep it still for 2 s after the program starts.
A mechanism gets weak during a matchMotor overheating (check temperature in telemetry), or too many motors sharing current.
Auto worked yesterday, falls short todayBattery charge. Swap batteries below about 70%.
Controller screen text doesn't changeText is sent every 50 ms per line in turn; very frequent changes on all lines show with a delay. Write only what changed.

Performance

The interpreter is slower than native PROS or vexide code. To keep the 10 ms loop on time:

  • Keep periodic() methods light; don't create objects (new Pose2ds, strings) every loop when you can avoid it.
  • Draw on the brain screen only when something changes.
  • Send telemetry only for what you're debugging; it's printed at most four times a second for this reason.
  • Let the path planner pre-compute trajectories on your computer (it does) and prefer the motor's built-in position control for simple moves.

Questions

Can I use this with PROS or VEXcode?

No: it's Java, running on Hydrozoa. It replaces PROS/VEXcode for your program, and uses the same V5 SDK underneath.

Is it competition-legal?

Hydrozoa programs are uploaded and run like any other user program, through VEXos, and respond to field control. As always, check the current game manual for programming rules.

Does it work on VEX IQ or EXP?

No, only the V5 brain (Hydrozoa targets V5).

Where's the source for a library class?

Every class has a page in the API reference, and in VS Code, Ctrl/Cmd-click a library class to open its source (the vendor library ships a sources jar).
