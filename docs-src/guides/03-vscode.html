Create a robot project, build, simulate and upload it, and add subsystems, commands and autos without leaving the editor.

Install it

  1. Get vex-command-based-0.1.0.vsix (build it from vscode-extension/ in this repository, see below).
  2. In VS Code open Extensions, click … at the top of the panel, choose Install from VSIX… and pick the file.
  3. Also install the Extension Pack for Java for code completion, and JDK 21.

Create a project

Open the Command Palette (Ctrl+Shift+P) and run VEX: Create a New Project. It asks four things:

QuestionExample
Start fromCommand-based template (6-motor tank drive, intake, planner autos) or V5 Clawbot
WhereThe folder the project goes in
NameTeam1234Bot: the folder name and the name on the brain's screen
Packagecom.team1234.robot

The result is a standalone Gradle project: your robot code in src/main/java/ under your package, the simulator in src/sim/java/, and VexLib installed as a vendor library in vendordeps/VexLib.json, the way an FRC project lists REV or CTRE. The library's classes are in the com.robojacks.lib package, so imports match these guides.

Build, simulate, upload

With a robot project open, the status bar shows four buttons:

ButtonRuns
Robot name · slotPicks the robot program, when the folder has more than one (this repository has two)
Buildgradlew assemble
Simulategradlew simulate: see Simulator
Uploadgradlew hydrozoaUpload; Ctrl+Shift+U in a Java file

Upload needs the Hydrozoa CLI. If it isn't installed, the extension says so and can run the install command in a terminal for you. VEX: Simulate Tuning Tests runs the simulator with --args=tune. Compile errors appear in the Problems panel.

These are also tasks of type vex, so they work from Terminal → Run Task and in tasks.json:

{ "type": "vex", "task": "upload", "robot": ":examples:clawbot" }

Leave out robot in a project the extension created; it has one robot.

Vendor libraries

VEX: Manage Vendor Libraries installs, updates and removes libraries, like WPILib's vendor dependency manager. See Vendor libraries.

New subsystems, commands and autos

Right-click a folder under src/main/java and open the VEX menu:

WizardWrites
New SubsystemA SubsystemBase with periodic() and an example command factory.
New Subsystem with a MotorAsks for the port, cartridge and idle mode. Writes a one-motor subsystem configured with VexMotorConfig, with forward and reverse commands, and adds <Name>Constants to your Constants.java.
New CommandA Command class with initialize, execute, end and isFinished. Lists your subsystems so it can call addRequirements.
New AutoA static factory built from AutoBuilder steps, ready to return from RobotContainer.getAutonomousCommand().

The package comes from the folder you clicked. Snippets: type vexbind, vexstartend, vexrunonce, vexnamed, vexmotorconfig or vexsequence in a Java file.

Building the extension

cd vscode-extension
node scripts/bundle.js        # packs the published VexLib, template/ and examples/clawbot/
node test/run.js              # tests
npx @vscode/vsce package      # makes the .vsix

Run the bundle step after publishing a new VexLib or changing the templates. Existing projects pick up a new VexLib through Check for updates.
